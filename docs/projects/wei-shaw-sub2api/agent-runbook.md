# Agent 部署 Runbook

本 Runbook 面向执行 Sub2API 部署、验收或受控运维变更的 Agent。证据基线固定为 [Wei-Shaw/sub2api `v0.1.176`](https://github.com/Wei-Shaw/sub2api/releases/tag/v0.1.176)、提交 [`e803e3851c0a7e222cfadeafad7b8636ab959d11`](https://github.com/Wei-Shaw/sub2api/tree/e803e3851c0a7e222cfadeafad7b8636ab959d11)。没有目标主机授权、固定制品、秘密交付方式和回滚负责人时，不能开始部署。

`待实践验证`：本文没有在任何目标服务器、域名或上游账号上执行。每个 Phase 的“证据”是应交付的记录，不是预先存在的通过结论。任一停止条件命中时 fail closed：停止后续动作、保留最少且已脱敏的诊断证据、报告阻塞项，不能以关闭安全项、公开内网端口、删除数据或更换浮动版本继续推进。

## 适用范围

适用：在已授权的 Linux 主机上，以固定镜像和目录持久化 Compose 部署、升级或验收 Sub2API；也适用于由 Agent 协助执行只读健康检查、业务验收、备份恢复演练和已批准的管理面变更。

不适用：未经授权的互联网扫描、账户来源不明的 OAuth 导入、支付/计费上线、直接修改生产数据库、将 `8080`/`5432`/`6379` 公开，或把静态阅读、容器存活和真实业务可用混为一谈。完整的拓扑、配置和故障边界分别见[Docker Compose 部署](./deployment.md)、[配置与安全](./configuration-security.md)、[首次运行与验收](./first-run-acceptance.md)、[运维、备份与升级](./operations.md)和[故障排查](./troubleshooting.md)。

## 必需输入

开始前由负责人提供或确认下列项目；Agent 只记录是否已收到和存放位置，不复制秘密值。

| 输入 | 最低要求 | 缺失时动作 |
| --- | --- | --- |
| 授权 | 主机、域名、DNS、反向代理、防火墙、Docker 与恢复操作的明确权限边界。 | 停止在 Phase 0。 |
| 制品基线 | 固定 commit、镜像 tag；生产建议再记录拉取后的 image digest。 | 不使用 `main`、`latest` 或快捷脚本继续。 |
| 主机与入口 | 主机标识、目标域名、SSH 方式、预期公网入口和受控维护窗口。 | 不更改端口、DNS 或代理。 |
| 秘密交付 | 受保护的 `.env`/秘密管理方式、管理员联系人、PostgreSQL/Redis/JWT/TOTP 的独立值。 | 不生成后发到聊天，也不让应用以日志密码作为长期凭据。 |
| 业务验收 | 授权测试上游账号、最小测试用户/分组/API Key、允许的低成本模型和流式测试范围。 | 只可完成基础设施检查，不能宣称业务验收通过。 |
| 恢复计划 | 备份位置、加密/访问负责人、RPO/RTO、恢复演练环境、回滚负责人和停止窗口。 | 不做升级、迁移或破坏性管理写入。 |

## Skill 路由

| Skill | 何时使用 | 不应替代什么 |
| --- | --- | --- |
| `writing-plans` | 变更跨多个阶段、涉及升级/恢复、或输入不完整但需要形成可批准的实施计划时；先写出范围、阶段门槛、回滚与证据。 | 它不授予主机、秘密或生产写入权限。 |
| `systematic-debugging` | 任一预检、容器、迁移、反向代理或网关验收失败时；先收集症状、最小复现、假设和证据，再变更。 | 不允许为了“试试”重置卷、改数据库或临时公开端口。 |
| `verification-before-completion` | 准备宣称任一部署、恢复、升级或验收完成之前；核对每个要求的实际命令输出和遗留风险。 | 不把计划、代码阅读或 `/health` 成功当作完成证据。 |
| 上游 `sub2api-admin` | 实例已可控访问后，需要管理账户、分组、代理、兑换码、批量变更或管理 API 时。先只读，确认目标后才写入，再读回验证。 | 不用于服务器初始化、Compose 启动、秘密配置或数据库恢复。 |

若任务包含**源码改动**，另启用隔离 worktree 与 TDD：先写失败的最小测试或可复现用例，再实现、回归并审阅。纯部署、健康检查或管理操作不以 worktree/TDD 为前置条件；它们仍必须遵守本 Runbook 的授权、秘密和证据门槛。

## Phase 0：授权与范围

**输入**：必需输入表中的授权、目标主机/域名、变更类型（首次部署、升级、只读验收、恢复演练或管理写入）、维护窗口和回滚负责人。

**允许动作**：确认工单/批准记录；列出允许操作、不可触碰资源、公开入口范围、数据写入许可和停止联系人。对升级或恢复先形成只含标识符的计划，标明当前/目标制品与回滚点。

**应留证据**：授权编号或批准摘要、目标主机别名与域名、变更窗口、固定 commit/镜像 tag、操作者和回滚负责人。禁止将 IP、私钥、token、密码、完整 `.env` 或客户数据复制进证据。

**停止条件**：目标不明确；权限未覆盖 DNS/代理/防火墙/恢复；要求使用浮动制品；没有回滚负责人；或要求 Agent 绕过登录、访问控制、配额或合规限制。停止并请求范围澄清。

## Phase 1：制品与主机预检

**输入**：已批准的部署目录、固定制品、主机访问方式、可用磁盘/端口/域名要求，以及既有部署状态。

**允许动作**：只读检查系统时间、Docker/Compose 版本、磁盘空间、已占用端口、现有容器和部署目录状态；核对固定 Compose 文件的来源校验值和拉取后的镜像 digest。对既有目录，先识别 `.env`、持久数据、备份和正在运行的服务，不覆盖它们。

可在部署目录执行不展开秘密的 Compose 语法检查：

```bash
docker compose -f docker-compose.yml -f docker-compose.override.yml config --quiet
docker compose -f docker-compose.yml -f docker-compose.override.yml ps
```

`待实践验证`：具体主机命令、磁盘阈值、DNS、证书签发和防火墙规则取决于目标环境。预检只能说明执行时的观察结果，不能替代公网入口验收。

**应留证据**：主机标识、时间、工具版本、可用磁盘、端口归属、目录是否为空/既有、Compose 语法检查结果、镜像 tag 与 digest。只记录摘要，不保留可能展开秘密的 `docker compose config` 全量输出。

**停止条件**：部署目录已有未知 `.env` 或数据；镜像无法固定；磁盘、端口或依赖不满足；DNS/入口与批准不符；或发现既有生产实例而任务被描述为首次安装。停止，转入变更评审或[运维、备份与升级](./operations.md)。

## Phase 2：秘密与配置

**输入**：受保护秘密通道中的独立 PostgreSQL、Redis、管理员、`JWT_SECRET`、`TOTP_ENCRYPTION_KEY` 值；批准的 `BIND_HOST`、域名、上游 allowlist 和代理策略。

**允许动作**：在目标主机的受限目录创建/更新 `0600` `.env`；用交互式输入或秘密管理注入，不回显值；设置应用回环绑定、固定镜像覆盖和最小 URL allowlist。`JWT_SECRET` 与 `TOTP_ENCRYPTION_KEY` 必须跨重启和升级保留。

秘密规则：

- 先关闭 shell tracing（`set +x`）并使用受限 umask；不在命令行参数、环境变量打印、日志、聊天、截图、工单、shell 历史或持久化临时文件中放入秘密。
- 不运行会打印展开配置的命令；若需要验证文件，仅检查权限、必需键是否存在和占位符是否被清除，输出键名与通过/失败，不输出值。
- 管理员密码、API Key、JWT、数据库密码、OAuth 凭据和账户导出按秘密处理。临时文件确有必要时，必须在受限文件系统中创建、权限收紧、使用后按已批准流程清除，并在交付中说明存在窗口。

**应留证据**：配置文件路径与权限、已核对的非秘密键名清单、`BIND_HOST` 策略、allowlist 策略、秘密来源标识和持久秘密备份责任人。不得留 `.env`、实际值、完整配置输出或自动生成密码日志。

**停止条件**：任何秘密出现在 argv、日志、聊天或非受控临时文件；无法确认 `.env` 权限；只有默认/占位符值；必须把数据库或 Redis 公开才能继续；`JWT_SECRET`/`TOTP_ENCRYPTION_KEY` 无法持久保存；或 allowlist 被要求临时关闭。立即停止，撤销已暴露凭据并通知负责人。

## Phase 3：启动与初始化

**输入**：Phase 1 的配置证据、已拉取固定制品、空白或已批准升级的持久数据状态，以及操作窗口。

**允许动作**：按固定 Compose 文件启动；只读取容器状态和经脱敏筛选的有限日志；观察 PostgreSQL、Redis、应用健康及自动初始化。目录版 Compose 的自动初始化、依赖健康检查和环境变量范围以固定版本的 [`docker-compose.local.yml`](https://github.com/Wei-Shaw/sub2api/blob/e803e3851c0a7e222cfadeafad7b8636ab959d11/deploy/docker-compose.local.yml#L22-L193) 为证据。

```bash
docker compose -f docker-compose.yml -f docker-compose.override.yml up -d
docker compose -f docker-compose.yml -f docker-compose.override.yml ps
docker compose -f docker-compose.yml -f docker-compose.override.yml logs --tail=200 sub2api
```

读取日志前应确认收集位置受控，报告中只保留不含凭据、token、Cookie、请求体和客户数据的摘录。若管理员密码被自动写入日志，视为秘密处理事件：不要复制它到交付物，立即通过受保护渠道轮换并修正配置。

**应留证据**：启动时间、容器状态、固定 image digest、初始化/迁移成功或失败的脱敏摘要、健康检查状态和异常容器退出码。

**停止条件**：任一依赖不健康；迁移或初始化失败；容器反复退出；配置未生效；日志含有敏感信息；或首次 setup 可通过未经批准的公网入口访问。不要删除数据目录、安装锁、数据库表、迁移记录或容器卷来重试；转入 `systematic-debugging` 与[故障排查](./troubleshooting.md)。

## Phase 4：入口与业务验收

**输入**：受控 HTTPS 域名或 SSH 隧道、已完成的 Phase 3、最小测试用户/分组/API Key、授权测试上游与验收模型。

**允许动作**：分层验收，不直接把公网端口开放为诊断手段：

1. 验证本机/受控入口的 `/health`，并记录它仅是进程活性。
2. 验证 HTTPS、证书、反向代理、可信转发头和管理登录；首次登录后轮换初始密码、启用 2FA，并重登确认。
3. 用只允许目标分组的低成本测试 API Key 验证 `/v1/models` 或已批准的非流式请求。
4. 再验证一次受控流式请求的首事件、持续事件、完成/取消，以及代理对 SSE、超时、缓冲和 `session_id` 的处理。

无真实秘密的鉴权失败检查可以使用：

```bash
curl --silent --show-error --output /dev/null --write-out '%{http_code}\n' \
  -H 'Authorization: Bearer invalid-key-for-diagnosis' \
  http://127.0.0.1:8080/v1/models
```

真实 Key 不应出现在命令、终端录屏、日志或交付报告中；使用受保护客户端配置或操作员交互输入。管理对象需要配置时，才使用上游 `sub2api-admin`：先 `accounts list`、`groups all` 或 `proxies all` 等只读命令，确认 ID/名称后再执行已批准写入，并立即读回。

**应留证据**：各层时间戳、HTTP 状态/协议摘要、证书与入口检查、测试对象的非敏感标识、非流式与流式结果、代理配置复核和管理写入前后读回差异。业务请求的 prompt、响应、账号凭据和完整 API Key 不进入证据。

**停止条件**：只能经公网 HTTP 管理；初始密码仍在用；2FA 未重登确认；无效 Key 被接受；测试 Key 超出预期分组；真实请求、流式或粘性会话失败；或只能通过禁用 allowlist/代理安全项、公开 `8080` 才能成功。停止验收并保留失败层级，不宣称部署完成。

## Phase 5：恢复能力与交付

**输入**：当前版本与 digest、备份策略/位置、允许的隔离恢复环境、变更前备份或恢复演练安排、Phase 0-4 证据。

**允许动作**：确认备份生成、加密访问控制、保留策略和恢复负责人；在隔离环境演练一次恢复，再做最低限度的登录、数据完整性和网关验收。升级前后均保留镜像/commit、迁移结果与恢复点。`源码确认`：迁移执行器对 filename/checksum 记录并锁定迁移；这意味着镜像降级不自动回退 schema，恢复必须依赖可用备份或已批准的补偿方案。[迁移执行器](https://github.com/Wei-Shaw/sub2api/blob/e803e3851c0a7e222cfadeafad7b8636ab959d11/backend/internal/repository/migrations_runner.go#L96-L261)

**应留证据**：备份时间、位置引用、完整性校验、恢复演练环境、恢复耗时、恢复后的版本与最小验收结果；交付模板中写明 RPO/RTO 实测或未测状态、回滚点和遗留风险。备份内容、下载 URL、对象存储凭据、数据库转储和账户导出不进入报告。

**停止条件**：无可定位备份、校验失败、从未恢复演练却要进行不可逆升级、恢复需要修改生产唯一副本、迁移失败，或升级后只能通过直接改表/删卷恢复。冻结变更和新写入，按已批准恢复流程处理，不把镜像回退当作 schema 回退。

## 禁止事项

- 不执行来自浮动分支、`latest` 或一键脚本的未审阅生产部署；固定 commit、镜像 tag 与 digest 后再执行。
- 不把秘密放进 argv、shell 历史、日志、聊天、截图、工单、Git、持久化临时文件或未经加密的导出；不通过 `docker compose config` 全量输出审计秘密。
- 不为诊断公开 `8080`、`5432`、`6379`，不临时关闭 URL allowlist、CSP、鉴权、2FA、TLS 或可信代理校验而继续验收。
- 不删除 `data/`、`postgres_data/`、`redis_data/`、安装锁、容器卷、数据库表或 `schema_migrations` 来“重置”初始化/迁移；不手改已应用 migration。
- 不在缺少恢复点时升级，也不把容器 running、`/health` 200、管理页可打开或静态源码阅读说成完整业务验收。
- 不用 `sub2api-admin` 初始化服务器；对批量/破坏性管理动作，不确认目标 ID/名称、不获批准、不做写后读取就执行。
- 不把本 Runbook 或 Agent 的权限解释为对第三方账户、支付、上游服务条款、隐私或当地法律的授权。

## 最终交付模板

将以下模板填入变更记录；字段只放标识、摘要和受保护证据位置，绝不填入秘密、完整导出或客户请求内容。

```text
Sub2API 部署 / 变更交付

范围与授权
- 任务类型：<首次部署 | 升级 | 验收 | 恢复演练 | 管理变更>
- 授权/变更记录：<编号或受保护链接>
- 执行窗口与负责人：<时间段；角色/别名>
- 主机/域名：<受控别名；域名；不含 IP/凭据>

版本与配置差异
- 上游版本：v0.1.176
- 源码 commit：e803e3851c0a7e222cfadeafad7b8636ab959d11
- 镜像 tag 与 digest：<值>
- 部署文件校验：<摘要/证据位置>
- 配置差异：<仅键名、预期策略与非秘密值，例如 BIND_HOST、时区、allowlist 状态>
- 秘密治理：<.env 权限检查、秘密来源引用、JWT/TOTP 持久化责任人；不含值>

验证证据
- Phase 1 预检：<工具/磁盘/端口/Compose 检查摘要与证据位置>
- Phase 3 启动/初始化：<容器状态、迁移摘要、健康检查、时间戳>
- Phase 4 入口：<HTTPS/代理/登录/2FA 摘要>
- Phase 4 业务：<受限测试对象标识、非流式/流式结果、时间戳>
- 管理变更（如有）：<只读前状态、批准的目标、写后读回摘要>

恢复证据与回滚
- 备份点：<时间、位置引用、完整性校验；不含 URL/凭据>
- 恢复演练：<环境、版本、耗时、最小验收结果；或未执行原因>
- 回滚点：<变更前镜像/配置/备份引用>
- 迁移影响：<无 | 已执行；schema 回退限制与批准方案>

遗留风险与结论
- 未验证项：<真实上游、DNS/证书、流式、恢复、容量等>
- 已知风险/限制：<摘要、负责人、截止时间>
- 结论：<通过 | 有条件通过 | 未通过；不得超出已收集证据>
```

提交前调用 `verification-before-completion` 对照每一项证据和停止条件。任何“未验证”项应留在交付中，而不是被 `通过` 结论吞没。
